# TON Blockchain & Cross-Platform OSINT Investigation Case

![Category](https://img.shields.io/badge/Категория-Blockchain%20OSINT-blue) ![License](https://img.shields.io/badge/Лицензия-MIT-green) ![Focus](https://img.shields.io/badge/Фокус-Пассивный%20анализ-orange)

## Краткое описание (Executive Summary)

В данном репозитории представлен структурированный кейс по **пассивной разведке по открытым источникам (OSINT)** и **анализу блокчейн-данных (Blockint)**. Основная цель исследования — оценить реальный уровень анонимности Web3-идентификаторов (анонимные номера TON `+888`) и отследить публичные цифровые следы между децентрализованными сущностями (блокчейн TON) и классическими платформами (Telegram, ВКонтакте).

> **Дисклеймер и этика:** Все чувствительные идентификаторы, персональные данные и реальные кошельки скрыты или заменены на анонимные заглушки (`REDACTED_ADDR`). Исследование проводилось исключительно в обучающих целях, для демонстрации методологии ИБ на основе публично доступных данных (Passive OSINT). Никаких активных атак или нарушений приватности не производилось.

## Методология и инструменты

Анализ выполнялся по строгому пассивному (неинтерактивному) сценарию для обеспечения максимальной операционной безопасности (OpSec):

* **Изоляция среды:** Исследование проводилось внутри изолированной виртуальной машины (Kali Linux) с использованием VPN-туннелей и исследовательских профилей.
* **Блокчейн-обозреватели:** Tonscan, Tonviewer и API маркетплейса Getgems для анализа транзакций и истории NFT.
* **Сопоставление сущностей:** Индексация открытых поисковых систем, архивные данные (Wayback Machine) и визуальный анализ паттернов.

## Основные этапы анализа

### Этап 1: Анализ следов в блокчейне (On-Chain)
1. Определение целевого TON-кошелька через публичную историю транзакций.
2. Сопоставление входящих и исходящих смарт-контрактов на Getgems.
3. Извлечение метаданных из истории владения анонимным номером TON (`+888 7XXX XXXX`).

### Этап 2: Сопоставление Web3 и Web2
1. Сверка исторических юзернеймов Telegram, связанных с покупкой NFT на Fragment.
2. Подтверждение связанных публичных никнеймов через кэш поисковых систем и исторические базы.
3. Идентификация связанных вторичных профилей в социальных сетях без прямого взаимодействия с объектом.

### Этап 3: OpSec и оценка рисков
1. Демонстрация того, как «псевдоанонимные» Web3-транзакции могут деанонимизироваться при повторном использовании юзернеймов в Web2 и Web3 экосистемах.
2. Оценка ошибок операционной безопасности объекта (повтор ников, временные паттерны активности в публичном реестре).

## Ключевые выводы и рекомендации

1. **Риски псевдоанонимности Web3:** Анонимный номер Telegram (`+888`) не гарантирует стопроцентной конфиденциальности, если связанный TON-кошелек взаимодействует с централизованными биржами или публичными NFT.
2. **Повторное использование никнеймов:** Использование одного и того же юзернейма на разных платформах остаётся главным вектором для пассивной деанонимизации через OSINT.
3. **Приоритет пассивной разведки:** Эффективные исследования на 100% опираются на публичные реестры, API и кэш поисковиков без прямого контакта с целевым профилем.
